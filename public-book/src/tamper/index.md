# 改ざんシナリオ

改ざんシナリオでは、票を集計入力から除外する操作と、表示する得票数を書き換える操作を再現します。前者では掲示板と集計入力、後者では計算結果と表示に不一致が生じます。

集計時にシナリオを一つ選択できます。S0 は変更を加えない基準です。S1・S3・S5 は一票を集計入力から外し、S2・S4 は画面へ出す得票数だけを変えます。

どちらの改ざんでも、STARK レシート自体は正常に検証できる場合があります。前者では「63 票を受け取り、一票の未提示を記録した計算」が正しく実行され、後者では「元の 64 票の正しい集計」がそのまま証明されるためです。検証画面は、この証明に結びついた結果を掲示板や表示値と比較して、集計全体の失敗を見つけます。

[各シナリオ](scenarios.md)に、インデックス 0 のユーザー票と 63 票のボット票に加える変更を示します。変更による検証結果の違いは、[チェック結果の対応表](detection-mechanism.md)にまとめています。
